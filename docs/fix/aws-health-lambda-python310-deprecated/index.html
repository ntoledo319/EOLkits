AWS Health Notification (Python 3.10)

[AWS Lambda] End of support for Python 3.10 runtime in AWS Lambda

[AWS Lambda] End of support for Python 3.10 runtime in AWS Lambda

What it means

AWS deprecated the python3.10 Lambda runtime on October 31, 2026; AWS no longer applies security or runtime patches to python3.10 functions.

Why it happens

Per the AWS Lambda runtime deprecation table, python3.10 (running on Amazon Linux 2) entered end-of-support on 2026-10-31. Existing functions continue to invoke, but AWS blocks creating new python3.10 functions on 2027-07-29 and updating existing ones on 2027-08-31. Upgrading also shifts the base OS from Amazon Linux 2 (glibc 2.26) to Amazon Linux 2023 (glibc 2.34).

How to fix it

  1. Inventory affected functions across regions (`aws lambda list-functions --query "Functions[?Runtime=='python3.10'].[FunctionName,Architectures]"`) and match them to SAM, CDK, Terraform, or Serverless files.
  2. Audit Python 3.12/3.13 standard-library removals (`distutils`, `imp`, `asyncore`, `smtpd`, `cgi`, `pipes`) before changing the runtime string.
  3. Rebuild compiled wheels (`cryptography`, `pydantic-core`, `psycopg2-binary`, `numpy`, `grpcio`) inside `public.ecr.aws/lambda/python:3.12` or `3.13` matching the function CPU architecture (`x86_64` vs `arm64`).
  4. Update IaC runtime to `python3.12` or `python3.13` and roll out behind a weighted Lambda alias canary with automatic CloudWatch alarm rollback.

Related deadline: Lambda Python 3.10 create/update restrictions — 2027-07-29.
