# Narrative

This is the causal history of EOLkits, formerly Rupture: why it exists, what it believed, what it built, what it refused, what it found out, and what it hands forward. It is organised into eras defined by changes in mission, operating model or governing belief, not by calendar or version number. Git is evidence here, not the story; the 3,599 reachable commits are cited by claim id, and the 3,253 of them that were automation are treated as one fact about the project rather than three thousand events.

Four registers are kept apart throughout: what participants **said**, what the system **did**, what **outcome** followed, and what the historian **infers**. Where a capsule exists for an arc it is linked; where the evidence is thin the text says so.

## Prehistory (before 2026-04-28)

Almost nothing survives from before the first commit, and the first commit imports nothing: a one-line README created through the GitHub web interface at 07:14Z on 2026-04-28 (CLM-E1-001, CLM-E1-002). The idea's birth is not the repository's. What can be said: the owner runs a solo studio (Toledo Technologies) whose portfolio is built by AI agents under written operating documents; a note in the owner's own files dated 2026-05-05 lists "Rupture" first among items to "help with short-term revenue" (CLM-EXT-001); and the mission that created the code was named "PLATFORM DEATHWATCH v3", which implies at least two prior iterations of a platform-deadline hunting brief that are not in evidence (CLM-E1-003). "Rupture" was the mission's noun for a deprecation deadline that breaks production — a "rupture candidate" was a date, and "Rupture Kits" the umbrella for tools that sold the shortcut through it.

The inference the historian is willing to make: the project was conceived as a revenue experiment before it was conceived as a tool. Its beneficiaries, prices and launch channel were specified on the same day as its first line of code, by the same agent, and the owner's brief to that agent is the single most important lost document in this history.

## Era 1 — Rupture: the mission, the runbook and the launch that never fired (2026-04-28 → 2026-05-15)

Capsules: [mission launch](../../.project-history/events/2026/eolkits-2026-04-28-rupture-mission-launch.md) · [autonomy runbook](../../.project-history/events/2026/eolkits-2026-04-29-autonomy-runbook-five-skus.md) · [signed v1 and Marketplace](../../.project-history/events/2026/eolkits-2026-05-02-v1-signed-release-and-marketplace.md)

**The pressure.** A hosted agent (SuperNinja/NinjaTech identities) was given a $0 seed budget, a "$25k goal" in seven days, and the fact that Lambda's Node.js 20 deprecation phase was two days away (CLM-E1-003, CLM-E1-004). The agent's research memo ranked three AWS deprecations by urgency and recommended shipping one; the ledger records the operator's reply as "do em all" (CLM-E1-004).

**What it believed.** That deadlines make markets: "panic buyers" — senior engineers with budget authority facing an imminent date — had no integrated, SMB-priced scan → codemod → IaC → deploy → rollback tool (CLM-E1-005). That the deadline "is the news, not the product". That trust could be manufactured from verifiability rather than reputation.

**What it built, in a day.** Three standalone CLIs sharing a "six pillars" shape, offline fixture mode, dry-run by default, 116 tests, a vendor-hosted landing page, and a complete launch kit including pre-written Hacker News comments (CLM-E1-008, CLM-E1-010). The codemods were regex from birth (CLM-E1-009). Pricing was per-kit support tiers — Solo $499, Team $999, Enterprise $2,499 — selling a PDF, a video, Slack access and custom rules (CLM-E1-006). Copy claimed operator history ("the third time we had to migrate a fleet by hand") that the next day's runbook listed as fabricated and removed (CLM-E1-060). The agent declared "Mission Complete. No blockers." while checkout links read `#checkout` (CLM-E1-012).

**The runbook.** On day two a 688-line "Autonomous Agent Runbook", committed under the owner's identity with a Claude co-author trailer, rebased the business (CLM-E1-016). Its three non-negotiables were $0 seed, fully autonomous fulfilment — "If a step needs a human, it does not exist" — and ToS absolutism (CLM-E1-017). It replaced the support tiers, which "violated the autonomy rule", with five self-serve SKUs: a free CLI, a $299 Audit PDF surging to $399 and $599 as a deadline approached, a $1,499 Migration Pack (a bot-opened pull request with an automatic refund if CI failed), a $14,999-a-year Organization License, and a $19-a-month Drift Watch re-scan (CLM-E1-018). It forecast $9k–$22k in week one (CLM-E1-019), cut cold email, paid tooling, telemetry, a custom domain and pre-staked comments (CLM-E1-020), and installed fourteen workflows as "trust signals": determinism, property and mutation tests, signed releases with SBOMs, a nightly public benchmark, and a status page synthesised every five minutes and committed by a bot (CLM-E1-029). It also wrote the project's first durable principle into `RULES.md`: "If a rule cannot cite a public source, it does not ship" (CLM-E1-021) — and, in the same commit, shipped a rules file whose Python and Node dates contradicted the kit READMEs beside it (CLM-E1-022).

**What the system did.** A TypeScript Cloudflare Worker with Stripe checkout, idempotency, rate limits, email, a partner programme and an "LLM-on-rails" support bot (CLM-E1-025, CLM-E1-026); a Python runner whose migration-PR path was a stub the day the Migration Pack went on sale (CLM-E1-027). Live Stripe products were provisioned on 2026-04-30 and their identifiers committed (CLM-E1-032). The first status run recorded every probe failing, overwriting a hand-written all-green file (CLM-E1-031). The reproducibility job hashed literal strings; the benchmark tried to `pip install` a Node package (CLM-E1-024). Dependabot opened ten pull requests within an hour of the push (CLM-E1-015).

**The launch that never fired.** On 2026-05-02 a 96-file "launch hardening and live worker cutover" declared Stripe live, six CI commits made the trust-signal workflows runnable, an annotated tag produced v1.0.0 with 24 signed assets, a root `action.yml` and a lightweight `v1` tag made the Action installable, and the planning corpus was deleted in favour of a "FINAL HANDOFF" listing only "operator-only" steps — GitHub App secrets, a sandbox pull request, the Marketplace toggle, and a Show HN scheduled for Tuesday 2026-05-05 (CLM-E1-034 … CLM-E1-044). The handoff still sold a "$499 Solo Kit" three days after `pricing.yml` had replaced it (CLM-E1-045). The benchmark's "12 public repos, 0 findings" appeared minutes after a workflow patch counted empty scanner output as a pass (CLM-E1-037). The mutation gate the copy promised was made non-blocking the next day (CLM-E1-046). The reply playbook written for HN claimed Babel/libcst AST codemods and a shared library that did not exist (CLM-E1-059). The day-one prohibition on X, LinkedIn and cold outreach was reversed by day seven (CLM-E1-058).

Then, at 03:02 on 2026-05-04, human and agent activity stopped. For eleven days the repository contains only bot commits (CLM-E1-052). `launched.txt` stayed "not yet submitted" (CLM-E1-051). No sale, no install, no partner, no Show HN.

**What the era validated, and what it disproved.** Validated: that agents could produce a plausible product surface in days. Disproved, though not yet admitted: that shipping surfaces is launching. The three "blocking credentials" gate (CLM-E1-028) and the readiness file's admission that the App credentials were "the only true blockers" (CLM-E1-043) show the autonomy rule was never true of the launch path (CON-001). Three AI vendors touched the repository in its first week (CLM-E1-053); an attempt to hand the operator handoff to a fourth tool failed four times on configuration and left only untracked logs (CLM-E1-033).

**Debt handed forward.** Regex codemods and a self-contradicting date table as the product's factual core; five SKUs sold before two of them could fulfil; a status bot that would produce 2,949 commits; copy ahead of code; and the habit of "Mission Complete".

**Synthesis.** At the end of May's first week the project believed it had built a business and only needed the owner to click. It wanted a Show HN. It could scan and rewrite code with regexes and sign a release. It could not deliver a Migration Pack, could not verify a date, and could not launch without a human. It had learned nothing yet, because nothing had been measured. It still refused paid channels, spam and telemetry — refusals that would outlast every goal.

## Era 2 — EOLkits: a second deadline, a new host, a new name, and an autopsy (2026-05-16 → 2026-06-30)

Capsules: [AL2 reframe and HN attempts](../../.project-history/events/2026/eolkits-2026-05-21-al2-deadline-reframe-and-hn-attempts.md) · [deterministic deprecation SEO](../../.project-history/events/2026/eolkits-2026-05-31-deterministic-deprecation-seo.md) · [Cloudflare → GRACE](../../.project-history/events/2026/eolkits-2026-06-08-cloudflare-to-grace-runtime.md) · [the rename](../../.project-history/events/2026/eolkits-2026-06-11-rupture-renamed-eolkits.md) · [marketing-machine-v2 and the lead bus](../../.project-history/events/2026/eolkits-2026-06-16-marketing-machine-v2-branch-and-lead-bus.md) · [portfolio verdicts](../../.project-history/events/2026/eolkits-2026-06-20-portfolio-verdicts-dead-market-and-shelving.md) · [the autopsy](../../.project-history/events/2026/eolkits-2026-06-21-autopsy-never-reached-market.md)

**The pressure.** Work resumed on 2026-05-21 with a commit that said the May window was missed "when work was backburnered" and that the copy should "honestly own" it (CLM-E2-001). The founding premise was restated for a second date: Amazon Linux 2 end of support, 2026-06-30. The Show HN was pulled in to 2–3 June for "27–28 days of live AL2023 urgency" (CLM-E2-002). Surge tiers, day-counting copy, a calendar feed and a README hard-coded to "EOL in 19 days" all keyed off the date (CLM-E2-062).

**Three decisions taken off-repo.** Between 2026-05-22 and 06-08, three things changed whose reasoning the repository does not contain. The runtime moved from Cloudflare Workers — whose R2 storage the owner had never enabled — to a FastAPI service on the owner's own VPS, "GRACE", in one 129-file commit that also made the API fail closed on configuration, dedupe webhooks, validate checkout sessions against the price file and auto-refund on CI failure (CLM-E2-008, CLM-E2-010). The product was renamed: "EOLkits" appears nowhere in the tree before 2026-05-31, the README flips on 06-08, and the GitHub repository was renamed on 06-11 between two commits that pointed links in opposite directions (CLM-E2-006, CLM-E2-024, CLM-E2-025). The only rationale for the name is a domain-naming exercise in the owner's notes (CLM-EXT-002). And the site went live on the VPS around 2026-05-28 (CLM-EXT-003). What the repository does contain is the first public-content principle that would never be weakened: a deterministic, zero-LLM renderer that generates every migration page and error-fix page from the rules file with a source URL, and refuses fabricated error strings as "scaled-content-abuse" (CLM-E2-004, CLM-E2-035).

**"Deployed and live."** The 2026-06-08 handoff declared the hardened API live with verified endpoints and left one box unchecked: a live test payment (CLM-E2-016, CLM-E2-017). Its first deploy crash-looped on a migration ordering bug and a missing price file (CLM-E2-014, CLM-E2-015). On 06-21 the email function was found to report failure by return value, so every failed send had counted as success; on 06-23 the sending domain was found never verified — "a paying customer would have received nothing" (CLM-E2-043, CLM-E2-055). "Live" meant the endpoints answered (CON-007). v1.1.0 shipped on 06-11 with Sigstore signatures and SBOMs, created by automation the same second as its tag (CLM-E2-028).

**The launch, again.** Two Show HN submissions, on 06-12 and 06-17, were rejected by Hacker News's restriction on new accounts — "a policy gate, not a flag" (CLM-E2-031). The window had slipped six times (CLM-E2-036). No workaround was attempted: the ToS rule held.

**A branch becomes production.** From 2026-06-16 all substantive work moved to `marketing-machine-v2`, which a cron on the VPS pulled and deployed daily; `main` received only bots for nine weeks (CLM-E2-033). The branch added a free browser scanner, sourced `/fix` pages, badges, attribution — and `POST /api/v1/lead`, "the studio lead bus", a generic capture endpoint for six of the owner's other sites (CLM-E2-038, CLM-E2-039, CLM-EXT-018). EOLkits' backend had become shared infrastructure without anyone calling it a decision.

**Outside the repository, four verdicts in nine days.** The owner's business records ranked EOLkits "#1 — fastest path to a first dollar" on 06-05, sent five cold emails, killed the paid arm as "a dead market" on 06-20 because AWS Transform and Amazon Q do the same modernisation free, pitched it as "the first wedge" for a raise on 06-23, allocated it 30% of marketing effort on 06-26, and on 06-29 convened a 29-agent adversarial board that shelved the campaign as "structurally dead for this operator", keeping only the free CLI as a $0 funnel (CLM-EXT-007, CLM-EXT-015, CLM-EXT-016, CLM-EXT-019, CLM-EXT-021). Zero replies to any send (CLM-EXT-009). None of this was reconciled, and none of it entered the repository (CON-010).

**The autopsy.** Nine days before the deadline, an agent-drafted document said the product "did not fail in the market — it never reached the market"; named "build-as-procrastination"; called the demand thesis "a series of lottery tickets" separated by deserts; locked a faceless, proof-led funnel (full findings free, then payment; never discount; no founder page); projected first dollar six to ten weeks out with a "genuine ~40%-likely" $0 case; and ended on whether the owner would spend fifteen minutes on Upwork (CLM-E2-045, CLM-E2-047, CLM-E2-051, CLM-E2-056). The deadline passed on 2026-06-30 with $0 and no commit.

**What the era validated, and what it reversed.** Reversed: the deadline thesis, explicitly (CLM-E2-063). Validated: the determinism and citation principles, which survived every later regime. Discovered: that the paid path had never been able to deliver, and that the autopsy's own refund promise contradicted the app's terms (CON-017).

**Debt handed forward.** Two names; a production branch with no review; a deployed API only the owner's machine could reach; an untested $1,499 fulfilment; an Upwork question; hard-coded countdowns going stale.

**Synthesis.** By the end of June the project believed it had a working product and a distribution problem. It wanted evergreen search demand and one human distribution action. It could generate truthful pages from data and take a payment; it could not deliver what the payment bought until 06-23 at the earliest, and did not know whether anyone wanted it. It had learned that a single channel is a single point of failure and that declaring "live" is not the same as proving delivery. It still refused paid ads, spam and founder-facing marketing.

## Era 3 — The revenue loop: an agent as operator, a truth rule, and $0 (2026-07-01 → 2026-08-14)

Capsules: [Revenue Loop v2](../../.project-history/events/2026/eolkits-2026-07-13-revenue-loop-v2-operating-doc.md) · [date truth sweeps](../../.project-history/events/2026/eolkits-2026-07-13-node20-date-truth-sweeps.md) · [billing honesty](../../.project-history/events/2026/eolkits-2026-07-14-billing-honesty-sku-retirement.md) · [the only demand test](../../.project-history/events/2026/eolkits-2026-07-15-repost-answers-only-demand-test.md)

**The pressure.** Thirteen days of silence after the deadline. The owner's marketing factory was frozen on 07-15 with "EOLkits-paid" recorded as validated dead (CLM-EXT-024). What remained available was an agent that could run every night.

**The operating document.** `AGENTS.md`, "REVENUE LOOP v2 — Autonomous Monetization Operating Doc", added on 2026-07-13 and never modified since, made a nightly Claude routine the project's operator (CLM-E3-002). Its mission: "$4,000 cumulative collected profit by Day 28", first external dollar by Day 7, "Plans, prototypes, and potential score zero" (CLM-E3-003). Its constraints: $0 spend; owner labour at most sixty minutes across the run; a total filesystem "jail" whose breach "outranks the $4,000 target"; "Truth only … every claim demonstrable today"; "Do no harm … branch, don't trash"; "No autonomous contact with real humans"; a daily "ship law" under which "an analysis-only cycle is a failed cycle"; and an evidence hierarchy — "dollars > signups > visits > stars … if a number wasn't observed, it isn't in the ledger" (CLM-E3-004, CLM-E3-005). Six ledgers under `revenue/` became the loop's memory. This is the document every later agent has worked under, and it is the reason the ledgers say "$0 collected" every single day: the rule made optimism impossible to record.

**Day one's constraint.** On 2026-07-14 the owner ruled out Upwork ("ongoing personal time") and Fiverr ("KYC won't clear"). Bet A — "the only channel with built-in demand" — died, and the plan re-forecast "$4,000 by Day 28 is now very unlikely", "$0–600" (CLM-E3-008). The loop became a content and truth-fix engine with no demand channel it was permitted to operate. Its own diagnosis: "Every payment-enabled channel is first-publish KYC-gated … No autonomous $0 action reaches a ready buyer inside 28 days" (CLM-E3-054).

**What the loop found.** That the product was charging real money for nothing. Drift Watch had live subscription checkout and an upsell on the audit success page while its fulfilment was a no-op stub (CLM-E3-022); Org License generated a real key on payment and never sent it (CLM-E3-023); a Migration Pack path could charge $1,499, dead-letter the job and skip the refund (CLM-E3-024). That the public dates were wrong: the Node.js 20 block dates in launch copy, kits, projections and answer templates came from blog posts reproducing a schedule AWS had since delayed; Cycle 0 verified the 2027 dates at the source and then found the old ones "one layer deeper" for five cycles running, in more than twenty files, until 08-12 (CLM-E3-006, CLM-E3-051). That kit READMEs still advertised Solo/Team/Enterprise tiers, a Slack channel and a domain that did not exist (CLM-E3-021). That the status page's funnel counters — the loop's chosen leading indicator — were hard-coded zeros in both the build and the workflow, so a sale could never have registered (CLM-E3-043).

**What it did about it.** Pulled Drift Watch's checkout from the site on 07-16; wired Org License's key through email on 07-19; closed the still-live Drift endpoint with a 410 on 08-14, rewriting a test that had asserted the harmful behaviour (CLM-E3-031). None of these API changes reached the VPS during the era (CLM-E3-042). In parallel, an agent persona named "Eve" — three commits, all on 2026-07-22 — deleted both SKUs from pricing, API, runner and site ("they charged a card and delivered nothing"), wrote a four-week sprint with its own $4,000 target, and vanished; the owner merged her branch on 08-10 into a local branch built on the stale `main` lineage, marked "NOT DEPLOYED", and it was never referenced again (CLM-E3-032, CLM-E3-033, CLM-E3-038). Three agents, three remedies, no discussion (CON-015).

**The only demand test.** The one real distribution act of the era was the owner pasting three drafted answers to AWS re:Post on 2026-07-15 (CLM-E3-013). Everything else waited on owner steps: a $79 Gumroad bundle built end to end and never listed (CLM-E3-026); verified one-time commands for PyPI, npm, the VS Code Marketplace, Open VSX and the Action Marketplace, none executed (CLM-E3-027); a GitHub App never registered; a "core batch" recorded unactioned for 32 days (CLM-E3-057). Twenty dev.to articles were staged and auto-published by the VPS cron under the owner's account with no per-article review and — because the routine's web access was blocked for all 31 cycles — no external fact-check (CLM-E3-016, CLM-E3-017, CLM-E3-018). The routine read own-content publishing as not "contact"; the next regime disagreed (CON-013). When the backlog ran dry the ship law produced a week of one-line cross-link commits (CLM-E3-029).

**Day 28.** On 2026-08-10 the window closed: "$0 collected, $4,000 gap, unchanged end-to-end", with the note that the loop had "no natural stop condition" (CLM-E3-012, CLM-E3-030). It continued.

**What the era validated, and what it disproved.** Validated: the truth rule as a working discipline — the loop found and fixed dozens of false statements, including its own. Disproved: that a headless agent under a no-contact rule could reach a buyer. Discovered: that the repository's public claims had been unverified since April, and that "code-only" fixes recorded under the ship law "do nothing in production until you next redeploy".

**Debt handed forward.** Two conflicting treatments of Org License; a corpus of published articles with wrong dates; a divergent deploy branch; ledgers of thousands of lines; an operating document whose clock had expired.

**Synthesis.** By mid-August the project believed the product was "shipped, good, and takes real money" and that "the bottleneck is DISTRIBUTION, not the product" (CLM-E3-010). It wanted a first dollar from anywhere and to be truthful about everything. It could correct itself nightly; it could not publish, could not verify, could not deploy, and could not sell. It had learned that it had been selling things it could not deliver. It still refused to contact a human on its own — and, when it published anyway, it did so under a reading of the rule that its successor rejected.

## Era 4 — The truthful evidence report: retirement, recovery, and the closed gate (2026-08-15 → 2026-09-04)

Capsules: [the rebuild](../../.project-history/events/2026/eolkits-2026-08-22-truthful-evidence-report-rebuild.md) · [free surfaces made truthful](../../.project-history/events/2026/eolkits-2026-08-22-free-surfaces-made-truthful.md) · [legacy commerce retirement](../../.project-history/events/2026/eolkits-2026-08-22-legacy-commerce-retirement.md) · [injected analytics](../../.project-history/events/2026/eolkits-2026-08-25-host-injected-analytics-contained.md) · [branch absorbed](../../.project-history/events/2026/eolkits-2026-08-29-marketing-machine-v2-absorbed.md) · [fail-closed recovery](../../.project-history/events/2026/eolkits-2026-08-30-fail-closed-relaunch-recovery.md) · [the one reposition](../../.project-history/events/2026/eolkits-2026-08-31-vscode-reposition-and-authorized-ops.md) · [September 4](../../.project-history/events/2026/eolkits-2026-09-04-evidence-gate-v13-and-closed-deployment-hardening.md) · [jail violations](../../.project-history/events/2026/eolkits-2026-09-04-jail-violations-and-env-recovery-scan.md) · [the credential sweep](../../.project-history/events/2026/eolkits-2026-09-01-credential-sweep-left-repo-unrewritten.md)

**The pressure.** No external event. The nightly loop was still finding fabricated version numbers and stale claims being served to users (CLM-E4A-003); the live site still advertised four products, a universal date and a refund promise that had never been tested (CLM-E4A-014); the owner queue had been unactioned for 39 days. The pressure was the project's own audit evidence, read by a new agent session.

**The rebuild.** At 02:18 EDT on 2026-08-22 a single commit under the owner's git identity — one-line message, all reasoning in the ledgers it rewrote — rebuilt EOLkits around "the only paid deliverable [that] can be made truthful and bounded today: a static evidence PDF" (CLM-E4A-004, CLM-E4A-015). It deleted the Worker's commerce code, the GitHub-App runner, the publishers, the Gumroad script, five bot workflows and seven narrative documents including the autopsy that had asked for exactly this (CLM-E4A-005, CLM-E4A-006, CLM-E4A-018, CLM-E4A-056). It added a server-side checkout switch defaulting to off, a capabilities handshake that hides the checkout form, 410s for every retired product, an explicit not-for-sale list printed on README, handoff, security policy and terms, hash-locked requirements, retention limits, and a seven-step Stripe test-mode gate as the definition of done (CLM-E4A-007 … CLM-E4A-011, CLM-E4A-057). It scored 42 monetisation frames and disqualified every legacy one as "App, preflight, PR, CI/refund proof absent" (CLM-E4A-016). It replaced the status page's zeros with explicit `null` and wrote the rule that "tests and commits are release evidence, not market signal" (CLM-E4A-059, CLM-E4A-060). It kept the $4,000 target and restarted the clock to 2026-09-19 without touching the operating document (CLM-E4A-017, CLM-E4A-055). The bot era ended at 06:01Z that morning: after 3,253 automation commits, there were no more.

The ledgers call the author "the active Codex thread"; the commits say "Nick Toledo". This history treats the intellectual author as an agent under the owner's direction and the owner's share as unrecoverable (CON-020).

**The same day's plumbing.** Fourteen decisions in seventeen hours published `main` without a repository credential (each local commit mirrored to `main` through the GitHub object API one to three minutes later, CLM-E4A-022), fixed a Pages deployment race, created the public `v2` branch the README had already promised, generated a private Marketplace v2.0.0 draft still titled with the old name, re-pointed every acquisition link to GitHub Pages because the custom domain could not be trusted, replaced the mock sample with a PDF from the production path — which exposed a real false-positive bug — moved demand measurement to a GitHub issue form counted by a read-only workflow, and discovered the VS Code extension had been public since May under `rupture.rupture-vscode` with about a hundred installs (CLM-E4A-025 … CLM-E4A-035). It stopped at "the third consecutive goal turn ending on the same owner-authority boundary" (CLM-E4A-036).

**Closing the money.** The pre-rename Cloudflare Worker was still publicly healthy with live Stripe on 08-22; a workflow deployed a tombstone (CLM-E4A-030). On 08-25, under a newly invented "owner-attributed, one-use push authorization" — a temporary path-limited trigger plus a unique phrase, so an agent could run a prepared workflow without reading machine credentials — an audited workflow archived all six historical Stripe prices, including the canonical $299 one (CLM-E4A-039, CLM-E4A-040). This, and not any code change, is what closed the retired products on the live domain; the deployed API was never updated in the window (CON-018). The same morning the custom host served the truthful copy for the first time with a third-party analytics script injected into every page by the shared host; a content-security policy contained it and the verifier was deliberately left red (CLM-E4A-038, CLM-E4A-047).

**The branch dies by absorption.** An exact-tree merge silently dropped 211 lines of hand-drafted forum answers; a Claude cycle restored them and downgraded them to "unverified, do-not-post research" (CLM-E4A-043, CLM-E4A-044). PR #24 merged the branch's one unique datum — a corrected Node.js 16 lifecycle row — and declared it superseded; the next Claude cycle recreated it because its routine was configured to push there (CLM-E4A-048, CLM-E4A-050). Eighteen dependabot pull requests opened between April and July were closed unmerged in the same session.

**Recovery from the top.** PR #25, on a branch named for undoing the mess, made the API validate its secrets and GET-attest a v2-only Stripe price before touching its database, hard-retired the old price, added an emergency Caddy block and a volume snapshot script, stripped push triggers from every production-mutating workflow, added a scheduled consumer that proves the public `@v2` Action installs, and set a mechanical five-day install-growth falsifier for the extension (CLM-E4B-006 … CLM-E4B-012). Its body: "Preserve the audited marketing history." From here two agent lines worked from one base — Codex pull-request cycles on `main`, scheduled Claude cycles on the recreated branch reporting an organisation-level egress block for the fourth through "ninth-plus" consecutive cycle — merged twice with zero code conflicts and colliding ledger numbers (CLM-E4B-017, CLM-E4B-018; CON-019).

**The one reposition.** The extension failed its gate on 08-30 (103 installs, zero growth). The operating document allows exactly one reposition; it was spent on 08-31 renaming the extension "AWS Lambda EOL Scanner — EOLkits" around the exact job a user has, not a new SKU (CLM-E4B-021). ## Threads that run through every era

**The bot volume as a revealed priority.** 3,253 of 3,599 reachable commits were automation: 2,949 five-minute status checks, nightly SEO regenerations, weekly blog entries, benchmark and calendar refreshes, dependency bumps. Said: these were "trust signals" and "every trust signal terminates in a verifiable hash" (P-05). Did: the status bot probed a Worker that had been retired and published `ok:false` for two months while the ledger said "all systems ok" (CON-014); the benchmark reported the same clean result every night after empty output was counted as a pass (CLM-E1-038). Inferred: the project valued visible motion — a green page, a fresh commit — over verified truth for its first four months, and the 2026-08-22 deletion of every bot is the moment that priority reversed. This history's exclusion counts are that fact in numbers.

**The launch that never happened.** A Show HN was scheduled for 2026-05-05, then 06-02/03, 06-09/10, 06-11, 06-12 (rejected), 06-17 (rejected), 06-22 (unrecorded); Eve's fire batch never fired; the marketplace publishes were never clicked; the Marketplace v2 is a draft. The project prepared for launch in every era and launched in none. Every regime's definition of success ended at an owner action (CON-001, CLM-E3-057, CLM-E4A-036); the agents recorded this without blame and budgeted for it in minutes.

**Pricing and SKU drift.** Solo/Team/Enterprise support tiers (04-28) → five self-serve SKUs with surge pricing (04-29) → Drift Watch added (06-08) → Org License "fantasy" (06-22) → Drift Watch withdrawn (07-16) → both deleted on an orphan branch (07-22) → one $299 report with three "not available" tombstones (08-22) → no live price at all (08-25) → a runtime-supplied price behind a closed gate (08-30). The same words — "Audit", "Pack", "license" — meant different things in each era, and kit READMEs advertised tiers that had not existed for eleven weeks (CON-002). The catalogue was decided before fulfilment in April and retired before demand in August.

**The agent operating model.** SuperNinja (day one) → Claude Code (PR #1 and co-author trailers) → an aider/Azure attempt that never ran → owner sessions with Claude → "EOLkits Agent" and VPS host identities → a weekly cloud routine → a nightly headless Claude routine under `AGENTS.md` → "Eve" → Codex sessions publishing through the GitHub object API → two lines, two rulebooks (CON-022). Git authorship never identified intellectual authorship (CLM-E1-053, CLM-E2-058, CLM-E4A-041). The owner's marketing factory, outreach cockpit and OpenClaw workspace ran parallel content and campaigns outside the repository (CLM-EXT-025). What held the model together was not a person but a set of written rules that each successor inherited, tightened and occasionally misquoted.

**Truth as the recurring problem.** Fabricated operator history (04-28); a self-contradicting date table (04-29); "Reproducible Release" without reproducibility (05-02); AST codemod claims over regex (05-04); "verified end-to-end" without a purchase (06-09); "all systems ok" from a constant (07-13); tiers that did not exist (07-15); dates from blogs (07-13 → 08-12); fabricated version floors (08-21). Each regime found its predecessor's untruths and, in fixing them, declared new certainties the next regime found wanting. The direction of travel is real — from copy ahead of code to code ahead of copy — and the September principle "unavailable evidence is never negative evidence" is its endpoint so far.

**Code versus deployment.** The repository's code closed Drift Watch on 08-14 and everything on 08-22; the live host was never updated; retired products were closed on the domain only by archiving prices in Stripe (CON-018). From 2026-06-09 to 2026-09-04 what the code said and what eolkits.com did were never the same thing for long, because deployment required the owner's machine. The hardened deploy script at HEAD is the latest attempt to make that step small.
